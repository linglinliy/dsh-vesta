## 2. 优先修复的问题

### N1 / P0：E3 实际向主窗口投递，不能证明后台画布拾取失败

`scripts/vesta-e3-background.ps1` 的 `PostedClick(IntPtr canvas, ...)` 最终调用为 `PostedClick($h, $sx, $sy)`，而 `$h` 是传入的根窗口。`Layout` 发现 wxGLCanvas 但没有输出其句柄。因此当前对照是“向主窗口投递”与“真实屏幕点击”，不是“向画布投递”与“真实点击”。

实现路径：枚举时返回 canvasHwnd，并验证 PID、根窗口归属和可见性；屏幕点只调用一次 ScreenToClient(canvasHwnd) 换算，再向同一 canvasHwnd 投递。当前 ClientToScreen/ScreenToClient 往返应简化。记录 screen/client 坐标、实际句柄/类名、PostMessage 返回值及前台状态。分别在前台和后台建立干净状态重测，交换试验顺序。投递返回成功也不代表业务成功。

验收：证明两种方式作用于同一文档、同一球、同一模式；输出各自结果。重测前将“画布拾取只能走前台真实输入”改为“当前真实输入成功，后台路径尚未有效验证”。正式产品仍可优先采用已成功的前台路径，不必等待后台研究完成。

### N2 / P0：E4 自动判据即使没隐藏也会通过

`scripts/e4-hide.mjs` 用历史文本存在 Atom 行判定 selectionSeen；用行数相等判定 restoredAfterEsc。现有清单三步文本完全一致，`textChangedAfterDel=false`，不能从这些字段推出当前选中、隐藏成功或恢复成功。历史 Atom 行也不会因取消选择自动消失。

此外脚本未检查 VESTA_GUI_TESTS；没有窗口仍 exit(0)；硬编码模块路径和输出目录；默认取首个进程，listControls('main') 未与 pid 明确绑定；缺少顶层 finally。GUIDE 中“需要 GUI 开关”与实际不符。

实现路径：先绑定专用测试副本文档和窗口；从当前截图定位球并实际选择，读取本次动作新增的 Atom 输出，而不是读取最后一条旧记录。随后在同一事务内执行 Del、抓取、恢复和核验，明确各步失败码。选中后截图不得悄悄调整布局再沿用旧句柄和坐标。结构不变应核对完整位点属性快照，不能只有行数。

图像验收至少包含目标局部区域、同元素另一实例对照区、固定相机与样式、变化是否只发生于预期对象、恢复是否接近干净基线。将 selectionObserved、identityResolved、effectVerified、structureUnchanged、restorationVerified 独立返回；信息不足用 unknown，不能以行数相同补成 true。

### N3 / P1：“球变淡”应与用户期望的“隐藏”分别验收

保存截图中的目标球仍可见，Del 后呈半透明或变淡，相关连线视觉也有变化。可以报告“观察到变淡并能恢复”，暂不能直接承诺“渲染中完全不可见”。

准备两个独立能力：A，VESTA 原生 Del 的显示效果；B，最终截图或导出中指定实例不可见。对 B 先用 GUI 和导出验证真实效果，不用结构删除冒充显示隐藏。用同一 Si 位点的另一个周期副本作对照，证明只影响选定实例。另测已有隐藏对象时 Esc 的影响范围，避免恢复本次操作时把用户原有隐藏状态一起恢复。

### N4 / P1：捕获成功不等于画布有效，截图函数还有布局副作用

`captureFullWindow` 调用 `win/shot.ps1`；后者每次 SW_RESTORE、MoveWindow、置前，并可能从 PrintWindow 回退到 CopyFromScreen。故不能仅由函数名或调用方式断言“PrintWindow、不依赖前台或遮挡”。整窗着墨率可能主要来自工具栏和文字，无法保证 GL 区域有效。

实现路径：把 normalizeWindow 和 captureWindow 分开。普通观测不修改窗口；测试规范化只在事务开始做一次，之后重新枚举几何。清单保存实际 method、返回值、捕获时间、window/client/screen 原点和裁剪范围；检查 GL 区域非空、帧是否更新。屏幕回退要核验归属和遮挡。PC1 结论应绑定当次返回 method，并用画布局部变化判定，而不是只看整窗差异。

### N5 / P1：PNG 证据链改善，但“解码尺寸”尚未实现

`scripts/export-png.mjs` 已使用运行目录、签名和 SHA-256，这是改进。但 width/height 来自 buffer.readUInt32BE(16/20)，只是读取 PNG 头；未解码图像，当前判据也未要求 height>0、PS 成功或后续对话框全部结束。截断或损坏文件仍可能被报 png-verified。

实现路径：采用现有环境可用的真实图像解码器完整加载像素，验证宽高、可读像素和非空内容；检查 PS status/error/signal，等待文件写完并稳定，明确超时；有残留导出对话框不能报整个流程成功。磁盘文件验证与流程验证分开报告。

`dismissFollowups()` 未显式将目标 pid/root owner 传入对话框查询，且按 `/Export|确认另存为/` 广泛匹配并点“是”。要求精确允许的状态和按钮，验证 PID/owner 链及当前导出会话。唯一目标路径下若出现覆盖提示，应先解释路径冲突并失败，不应自动同意。runId 建议增加随机部分并独占创建目录，避免同秒碰撞。

### N6 / P1：清除选中与模式映射应使用独立基线

候选映射仍含绝对屏幕 y 坐标；换布局即失效。候选 5–7 没出现黄色只能说明当前组合未触发标记，不能证明这些模式没有选择能力。菜单枚举无 select 字符串仅证明该次枚举无匹配项，不能排除其他取消选择入口。

先用一个从未选中过的副本作为每条试验起点；若无法清除选中，每条重建测试文档，不让残留状态污染下一条。重建仅针对测试副本。记录工具图标实际矩形、相对于工具栏的坐标、提示文字或截图锚点、操作手势及行为，不把候选索引当模式名称。黄色识别限制在目标区域，并增加非蓝色原子、黄色原子和黄色背景的样例。

## 3. 交付到正式工具的实现顺序

1. **会话与观测**：提供绑定到 pid/rootHwnd/documentToken 的会话；观测返回 screenshotId、geometryRevision、DPI 感知实际状态、原图尺寸、裁剪变换、画布矩形、当前文档与图像。DPI 声明失败不能静默当成功，避免手工再乘 1.25 造成二次缩放。
2. **选择工具**：例如 vesta_select_visible(sessionId, screenshotId, geometryRevision, point, coordinateSpace)。点坐标明确属于哪张截图；观测已过期则重新拍摄定位。前台、焦点、坐标换算、点击、反馈读取在一个串行事务中完成，输出新的 selectionToken 和本次身份反馈。
3. **单实例显示操作**：例如 vesta_hide_selected(sessionId, selectionToken)。令牌绑定文档、视图和实例，文档/视图变化即失效；执行前再次核验选中。按实测语义报告 faded 或 hidden；不匹配预期则失败并保存证据。
4. **恢复**：明确原生 Esc 是恢复哪些对象，再决定是否能提供恢复本次操作接口；若做不到精确恢复，工具说明能力边界，不伪装为通用 undo。
5. **可靠导出**：复用同一会话和对话框状态机，返回文件、哈希、真实解码结果和流程完成状态。

工具名为建议，不要求机械增加这些名称；可以扩展现有入口，但 index.js 中必须有对应 schema、处理函数和帮助说明。只交实验脚本不算完成 DSH 集成。
