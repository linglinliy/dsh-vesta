# VESTA 后续详细实施方案：从单球操作到完整窗口控制

> 2026-10-30。配合 [总规划](VESTA-INTERACTION-ROADMAP.md) 与 [最新复核](VESTA-LATEST-REVIEW.md) 使用。本文是建议实施规格，不表示相关功能已完成，也不假定尚未验证的 VESTA 行为成立。优先通过真实窗口键鼠完成用户工作流，以截图确认结果。

## 1. 将最终目标写成用户能够验收的任务

“轻松操作”应意味着：用户描述目标，DSH 能识别当前窗口、理解当前文档和视图、规划操作、执行、观察结果、纠正错误，交付能保存或导出的结果。用户无需提供每一步坐标，也无需手动恢复焦点、寻找工具或关闭残留对话框。

建议用以下完整任务驱动开发，而不是用 API 数量衡量完成度：

| 任务 | 用户表达示例 | 必须交付的效果 |
|---|---|---|
| 当前窗口接管 | 操作我已经打开的这个结构 | 绑定正确窗口和标签，观察时保留原始布局 |
| 单实例选择 | 选择画面右上方最外侧的那个 Si 球 | 返回标注图与身份；有歧义时明确候选 |
| 单实例显示 | 只隐藏刚才这个球 | 明确是消失还是变淡；其他周期副本不误改 |
| 视图调整 | 转到能看清这一层的方向，放大一点 | 图像证据确认方向与构图，点选坐标随视图更新 |
| 结构编辑 | 修改这个位点的占位率 | 定位数据行，核对单位与属性，保存后重开检查 |
| 批量显示编辑 | 把氧球缩小，保留硅球大小 | 生效范围可解释，避免误改全局偏好 |
| 晶胞与边界 | 显示两倍 a 方向，保持 b/c 不变 | 边界参数正确，结构源位点不被当作渲染副本删除 |
| 测量 | 测量这两个球之间的键长 | 两个实例身份、距离及单位一致；不混入旧测量记录 |
| 体数据 | 打开电荷密度并调整等值面 | 文件、当前数据集、等值、正负面与样式都有可读证据 |
| 文件交付 | 保存工程，再导出透明背景高清图 | 工程可重开；图像真实解码，背景与尺寸符合要求 |

透明背景、高分辨率和具体文件格式均需按当前 VESTA 版本实际验证；未验证时返回 unsupported 或 unknown，不能仅凭扩展名承诺。

## 2. 开发顺序与阶段退出条件

### 阶段 A：把现有实验变成可信证据

先修最新复核中的 E3 句柄、E4 假通过、截图布局副作用、PNG 文件头替代解码等问题。后台点击研究可以暂缓，前台成功路线应先交付。

退出条件：同一个已知测试副本能从未选中状态开始，通过正式入口完成选择和局部显示变化；省略关键动作时验证器必须拒绝通过。

### 阶段 B：一条完整单球闭环

顺序为 attach → observe → resolve target → select → verify selection → change visibility → verify effect → restore → export。测试用新副本，真实用户窗口保留原有状态。无法精确恢复的步骤必须在能力报告中明确。

退出条件：连续 10 次独立运行完成；每次开始于干净副本；正确率分母包括失败和超时。这个次数只是早期门槛，不是普适可靠性的证明。

### 阶段 C：窗口、DPI、遮挡和用户干预

覆盖移动、最大化、缩放比例变化、多标签、弹窗和手动旋转。重点验证系统会拒绝使用过期坐标，而不仅验证正常点击。

退出条件：发生状态变化时能重新观察和定位；不能确认时停止当前动作并给出证据，不能点击其他应用。

### 阶段 D：扩展高频工作流

依次增加视图与构图、边界与样式、测量、结构编辑、体数据、保存导出。每类都交付完整工作流、失败恢复和能力状态，不能只完成菜单能打开。

### 阶段 E：自然语言任务与长流程

把可靠的小操作组合成任务执行器；支持中途观察、失败后续做、取消与恢复。长任务每完成一个子目标保存检查点，不把全部步骤一次性盲目发送。

## 3. 软件模块应如何拆分

建议沿用 Node + PowerShell 宿主，逐步抽出以下职责，不要求一次重写 core.js：

| 模块 | 责任 | 不应承担 |
|---|---|---|
| SessionManager | 绑定进程、主窗口、文档、会话锁、退出清理 | 推测鼠标目标 |
| Observer | 捕获、控件枚举、当前文字、几何和 DPI | 截图时移动窗口 |
| CoordinateMapper | 截图/裁剪/客户区/屏幕坐标变换 | 检测球体身份 |
| InputExecutor | 前台真实键鼠、按键释放、按动作记录 | 判断用户任务完成 |
| TargetResolver | 从截图和语义识别控件/球/数据行 | 随意发 Del 验证猜测 |
| SelectionVerifier | 本次标记、文本增量、身份和候选关系 | 用历史 Atom 行代替当前选中 |
| WorkflowRunner | 有条件状态机、超时、重试、检查点 | 在未识别弹窗上反复 Enter |
| ArtifactVerifier | 工程与图像产物核验 | 把文件存在当作完整成功 |

全局只保留一个真实输入队列。两个 VESTA 会话可以并存，但不能同时控制同一台机器的鼠标键盘。自动任务之间使用调度锁；检测到用户主动操作时结束当前微事务、释放本任务按键并重新观察，避免与用户争抢。

## 4. 观测与坐标协议：解决 DPI 问题的长期办法

每张截图应带元数据：sessionId、documentToken、screenshotId、capturedAt、rootHwnd、canvasHwnd、captureMethod、dpiAwareness、windowRect、canvasClientRect、canvasOriginScreen、imageSize、cropOrigin、displayTransform、geometryRevision、viewRevision。

geometryRevision 表示窗口位置、尺寸、DPI 或面板布局变化；viewRevision 表示旋转、缩放、边界、结构、样式等目标投影变化。二者不同：窗口没移动，球也可能因旋转而换位置。

坐标建议统一为截图原始像素输入。若 DSH 展示的是缩略图，必须同时保存缩略图到原图的映射。例如：原图裁剪后又缩小，先执行 `imagePoint = cropOrigin + previewPoint / previewScale`，再由记录的变换映射到客户区或屏幕。窗口截图可能含边框，不能把画布客户区原点当作整张窗口图原点。

禁止全链路额外乘固定 1.25。DPI 感知统一后应基于实际 API 输出坐标；缩放因子属于截图呈现映射，不等同于系统 DPI。

执行点击前：

1. 核对文档和窗口仍存在、可见、没有被目标模态框阻塞。
2. 重新读取实际几何；与观测版本不同则作废原始 point。
3. 对球体操作，还要确认视图版本和目标局部内容没有改变；文字光标闪烁等无关变化不宜使整张图都失效。
4. 激活并验证前台窗口，确认焦点属于目标；完成客户区到屏幕换算。
5. 截图取证后执行一次输入，再等待可观察反馈。

缩略图、负屏幕坐标、多显示器和裁剪都通过同一转换层处理；对越界坐标直接失败，不能夹紧到边缘继续点击。

## 5. 独立键鼠事务的具体执行规则

一次事务只做一个有可验证结果的微操作，比如“选择一个球”或“修改一个输入框”。多动作长事务容易因用户干预和弹窗失效。

建议状态机：

`OBSERVE → VALIDATE → ACQUIRE_INPUT → FOCUS → REVALIDATE → ACT → WAIT_EFFECT → VERIFY → RELEASE`

失败时进入 `RELEASE → CAPTURE_FAILURE → RETURN_STATUS`。只有明确定义的恢复步骤才能进入恢复流程。

- 点击：光标移动后确认当前命中窗口属于目标根窗口，鼠标按下/释放均有结果记录。窗口命中只是输入归属证据，不是球命中证据。
- 双击：同一客户区坐标和同一视图下执行；明确间隔；执行后观察选择，不凭“发送两次”报成功。
- 拖动：起点定位、逐段移动、终点释放；旋转/平移/框选等手势分别验证，不能共享同一结果判据。
- 输入文本：聚焦目标字段、全选、输入、读回、确认提交。若读回失败，用局部截图或对话框确认结果；不能盲按下一步。
- 快捷键：分开记录修饰键按下、主键、修饰键释放。finally 仅释放本任务按下的键，避免破坏用户原本按住的键状态。
- 滚轮：明确目标控件及焦点，每一小批滚动后观察缩放，避免鼠标在侧栏时把侧栏滚动当作画布缩放。
- 超时：区分“尚未观察到结果”和“确定没生效”。前者不能立即重发切换、删除或保存动作。

起步可配置焦点等待上限、短动作超时和文件导出超时，但以状态变化为准，不依赖固定 Sleep 推断成功。保存原焦点和光标；若用户已经主动切到别处，不强行把窗口恢复回来。

## 6. Select 与单球目标解析的详细路径

### 6.1 将“球”与“原子位点”分开建模

选择对象建议包括：siteId、元素/标签、空间群操作（可解析时）、周期平移、分数坐标、屏幕包围框、深度歧义、viewRevision。未知字段保持 null。

例如同属 Si2 的两个周期副本可以是不同 instanceId；只识别到 Si2，仍不足以证明选择了画面右上方的那一个。instanceId 是当前文档/视图下的引用，不能承诺跨重开、重建或改变边界仍有效。

### 6.2 先用简单目标建立可靠选择

第一批只选择：单个无遮挡、球面足够大、颜色与背景容易区分的目标。蓝色阈值只能作为该测试夹具的检测器。后续增加连通区域、圆形特征、局部轮廓、模型视觉定位等方案，通过实际样例评估，不能直接套到所有元素。

文字描述如“右上角”先转为多个候选的空间排序；标注候选图并结合元素、标签和邻接关系消歧。如果两个球完全重叠，先采用已验证的旋转/缩放拆开，重新截图定位。保存视图状态，能否恢复精确相机需另行验证。

### 6.3 本次选择至少用两类反馈核对

第一类是当前局部视觉反馈；第二类是本次文本区追加的 Atom/状态栏身份。读取文本前保存基线长度和尾部内容；点击后识别新增段。若文本被清空、截断或重排，重新建基线，不能继续按旧偏移截取。

测量相关 Bond 行不能代替球身份；多选状态应独立表示。颜色标记消失、旧文字仍存在时，不能延长旧 selectionToken。

### 6.4 取消选择作为独立研究任务

建立未选中 → 选中 → 尝试取消 → 重新选择的实验。逐项研究真实 Esc、目标工具下点空白、其他已观察到的入口；每项用新副本起始。分别记录选中标记、半透明状态、文本和状态栏变化。

如果暂时没有可靠取消方法，模式映射用新副本隔离继续推进；产品中返回 selectionUnknown，要求重新观察。不要让取消选择研究阻塞所有其他工作，也不要假设 Esc 既取消选择又只恢复本次隐藏。

## 7. 隐藏、变淡、删除与恢复的契约

建议把动作语义写进工具参数和返回值：

- `requestedEffect: invisible`：最终视图/导出中目标实例不再可见。
- `observedEffect: faded`：观察到变淡，不能将 invisible 任务报为完成。
- `removeStructuralSite`：修改结构数据，需要不同入口及完整属性核验。

若原生 Del 只能达到 faded，继续调查是否存在其他已验证的显示入口；无法实现时如实报告当前能力。不得偷偷删除结构位点或用图像涂白冒充 VESTA 中隐藏成功。

效果核验使用三个区域：目标球核心、与目标相连的局部区域、另一个同位点副本。球核心变化证明局部效果，对照区域帮助发现整组误改。恢复对照干净基线，不只对照选中标记尚在的图。

恢复方案按可靠程度递进：原生精确恢复 → 重放已记录且验证过的显示状态 → 在测试副本中重开基线。重开副本不能自动用于用户未保存的原始窗口。若只能恢复所有隐藏对象，公开声明影响范围，不能称为 undoLastHide。

## 8. 对话框和表格操作也要形成独立闭环

每种对话框建立状态描述：标题/类名/owner、关键控件、预期前驱、允许动作、成功条件、超时后的处理。标题仅是一个特征，不能全局找到含 Export 的窗口就点 OK。

对列表编辑，优先按实际列内容识别目标行，再核对行的属性，而不是永远点击第 N 行。排序、滚动、插入、删除和语言都会改变索引。编辑后读回整个受影响字段；保存后重开工程确认，尤其是只在预览中生效的设置。

参数输入协议区分绝对值、相对增量、单位和应用范围。例如“球变小一点”可映射为当前值的某个温和比例，并在局部预览确认；“占位率 0.5”必须按精确值和合法范围执行。用户意图涉及不同语义时，只澄清关键歧义，常规已授权步骤无需重复确认。

## 9. 错误分类与重试策略

| 状态 | 处理 | 是否重发 |
|---|---|---|
| staleObservation | 重拍、重新解析目标 | 不复用旧坐标 |
| wrongForeground | 重新激活并核验一次 | 只重试焦点步骤 |
| unknownDialog | 保存图与控件树，识别后规划 | 不发送通用 Enter/Esc |
| selectionAmbiguous | 返回标注候选，或调整视图再观察 | 不执行隐藏/删除 |
| effectUnknown | 补拍与读取反馈 | 不立即重复切换动作 |
| targetGone | 失效令牌，重新绑定 | 不沿用句柄 |
| exportIncomplete | 检查对话框与文件写入状态 | 不把旧文件当新结果 |
| userIntervened | 结束微事务、重新观察或等待继续 | 不争抢输入 |
| unsupported | 给出具体能力边界与替代路径 | 不无限重试 |

设置有限重试预算，例如焦点恢复最多一次、目标重定位最多两次；达到预算返回最后状态与证据。每次重试重新观察，记录是否可能已生效。旋转、缩放、隐藏等动作一般不具有幂等性，不能复用普通网络请求的重试思路。

## 10. 自动化验收应怎么设计

### 10.1 必须加入的反例

1. 文本区已经存在 Atom 行，但当前没有选中：不得判 selectionObserved。
2. 故意不发 Del：不得判 effectVerified。
3. 隐藏的是旁边球：不得判目标成功。
4. 选择后旋转视图：旧 selectionToken 按契约失效或重新验证。
5. 用户切换到另一个同名 POSCAR 标签：不能只凭标题继续执行。
6. 截图缩为 50% 后点选：换算仍命中原图目标。
7. PNG 只有合法头或被截断：解码验证必须失败。
8. 其他应用有同名 OK 按钮：不得点击。
9. 原先已有隐藏对象：恢复本次动作不能无声改变其他状态。
10. 空白/旧 GL 帧但工具栏正常：不得将截图判为有效业务证据。

### 10.2 回归矩阵避免组合爆炸

先固定一个结构覆盖全部流程，再逐项改变一个变量：DPI、尺寸、窗口位置、颜色、球半径、视角、边界、标签数量。之后选择关键组合，比如混合 DPI + 窗口移动、遮挡 + 屏幕捕获回退、多标签 + 同名文件。混合 DPI 等没有硬件条件的条目明确未测。

结构夹具至少涵盖：当前二位点多渲染副本案例、多元素颜色、前后重叠球、较密结构、已有隐藏对象、非正交晶胞。具体数量随验证需要扩展。

统计任务成功率、错误成功率、目标误选率、人工接管率、重试次数与耗时。开发初期首先压低错误成功率：失败可以修，错误地报告完成会污染后续整条任务。

## 11. 证据包与当前能力表

建议目录：

```text
run-<时间>-<随机后缀>/
  manifest.json
  environment.json
  actions.jsonl
  fixture/
  observations/
  annotations/
  outputs/
  failure/
```

manifest 汇总实际会话、夹具/脚本版本、能力项、每步结果和产物 SHA-256。actions 每条记录 actionId、前置观测、目标引用、实际输入后端、起止时间、结果状态、证据路径。失败同样保留完整证据，不能只收集成功截图。

维护一个可机读的 capability-status.json，例如 supported、experimental、unsupported、unknown 四种状态，加 testedVersion、environment、evidenceRunId 和限制。Markdown 表格从其生成；不要在多个文档分别维护相互冲突的“已完成”。

通过的能力可以是“此版本/此环境前台单击选择已验证”；不要直接扩大为“任意版本 Select 完全可用”。

## 12. 建议交给 DSH 的下一批任务

### 工作包 1：验证基础修复

修复 E3 画布句柄、E4 当前选择判据和失败退出、所有 GUI 脚本开关与 finally；抽出统一 runId/证据写入。交付代码差异、反例测试、一次成功和一次故意失败的证据。

### 工作包 2：统一观测与坐标

拆分截图与布局修改，新增观测元数据与变换函数。交付原图/缩略图/裁剪映射案例，以及移动窗口后旧截图拒绝执行案例。纯坐标转换可用确定性单元测试，不必为每个低层包装重复写镜像测试。

### 工作包 3：正式选择入口

在正式工具 schema 中接入 observe 和 select；建立 selectionToken。交付 DSH 发起的完整调用记录、目标标注图、当前身份和状态。不得依赖手动预先选中。

### 工作包 4：显示效果与恢复

验证 faded/invisible 差异、同位点副本范围、已有隐藏对象恢复范围。交付明确能力契约和正式工具案例；不能实现的效果明确标记，不以探针结果冒充支持。

### 工作包 5：导出与工程保存

对话框绑定、真实图像解码、文件稳定性、残留弹窗和工程重开核验。交付有效产物和损坏文件被拒绝的反例。

### 工作包 6：扩展工作流

按视图/边界/样式/测量/结构/体数据顺序推进，每批只增加一到两条完整工作流。达到前一阶段退出条件后再扩大任务范围。

最小可交付成果不是“更多脚本通过”，而是用户在已打开的 VESTA 中说出具体目标，DSH 能独立完成、正确核验，并在失败时留下可定位原因的证据。
