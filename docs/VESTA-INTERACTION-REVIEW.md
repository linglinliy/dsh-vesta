# VESTA 交互实现复核与下一轮改进建议

> 2026-10-28｜针对 DSH 最新文档和未提交代码的复核。  
> 范围：`VESTA-INTERACTION-ROADMAP.md`、`VESTA-INTERACTION-FINDINGS.md`、`VESTA-M0-M5-TESTREPORT.md`、`core.js` 和 `win/vesta-ui.ps1` 的增量改动，以及本机部分原始证据。  
> 本次只审阅文档、源码及已有文件，没有操作 VESTA，也没有重新运行 GUI 测试。DSH 报告的成功与本次独立复核的结果应分别看待。

## 1. 当前判断与下一轮目标

已有进展：报告记录了本机 VESTA 版本、真实输入探针、另存工程、样式和缩放操作，并发现 SendInput 结构体定义及模态调用阻塞问题。下一轮应集中解决“原生手动选取基线 → 准确命中 → 自动选择 → 隐藏 → 验证”，暂缓扩大新功能。

当前最缺的证据是：**同一结构、同一布局、同一已知目标上，原生手动操作是否可以选中，以及它与自动输入在何处产生差异。** 没有这个对照，仅遍历图标、延长按压时间或统计黄色像素很难区分模式、坐标、输入和验证方式四类问题。

建议状态如下：

| 能力            | 审阅后的状态            | 依据与缺口                                       |
| ------------- | ----------------- | ------------------------------------------- |
| 基础输入与菜单动作     | DSH 报告局部成功        | 不推广到所有目标、焦点条件和画布拾取                          |
| Select 模式识别   | 未确认               | 工具栏像素变化不能给出模式的语义名称                          |
| 自动选中指定显示球     | 未完成               | 缺少可信的原生选中对照和成功证据                            |
| 隐藏/恢复指定球      | 依赖选中，未验收          | 不能用边界变化或结构表删行替代                             |
| 另存工程          | 报告成功；文件存在及格式标记已复核 | `uia-final.vesta` 存在；尚未独立重开验证完整工程状态         |
| PNG 导出        | 未完成               | `exported.png` 文件头为 TIFF，且文件仅 206 字节；完整性未证实 |
| 结构删行          | DSH 报告局部成功        | 当前源码仍需完善目标对话框归属及真实结果核验                      |

## 2. 需要修正的归因与文档表述

### 2.1 版本差异是线索，尚未证明是失败原因

将“3.90.9a 不支持双击选中”改为“现有自动化序列在 3.90.9a 中未复现双击选择；原生手动操作待对照”。失败可能来自模式、目标坐标、窗口布局、真实事件目标、输入序列或验证条件；仅凭构建版本与旧手册不同，不能排除这些因素。优先查本机 Help 对应手册和工具提示，记录确切的选择入口。

### 2.2 工具栏哈希变化只证明画面状态变化

移开鼠标后颜色/哈希变化可排除一部分悬停干扰，但仍可能是焦点、按压态或其他模式，不能独立证明切到了 Select。用工具提示、可访问名称、实际按钮状态或对已知球的选择行为交叉验证。若接口返回 8 个按钮的命令 ID 都为 0，先确认读取方法、跨进程数据传递和结构布局，再断定是自绘控件的固有限制。

### 2.3 Text Area 行数与黄色像素不是充分判据

行数不变可能是覆盖、滚动、读错控件、折叠或根本未选中；没有新输出不能证明本版本不记录拾取。黄色像素判据也依赖配色、主题和选中样式。先用原生手动选择确认真实反馈，再定义解析或视觉检测方式。多选身份暂时不可读不阻止实现单球的视觉选择，但输出必须区分“可见选中已确认”和“精确晶体学身份未知”。

### 2.4 SendInput 修复不能解释所有其他通道的失败

报告中将 `WM_SETTEXT` 的失败也归因为 SendInput 结构体错误，因果关系不成立：两者不是同一个 API。应分别写明“消息写入未生效，具体原因待查”和“修正 SendInput 结构体后，真实键入成功”。同理，菜单可点击只证明该目标和时刻的输入通道可用，不能排除后续画布操作的焦点/命中问题。

Microsoft 要求 SendInput 的 `cbSize` 与原生 INPUT 尺寸相符；INPUT 包含鼠标、键盘及硬件输入联合体。建议按宿主架构声明完整结构并校验尺寸与偏移，不把 40 字节当作跨架构常量。返回插入事件数也不代表 VESTA 完成目标动作。记录事件数、宿主位数、结构尺寸及紧邻失败调用获取的错误；不能用成功后的旧错误值归因。[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[INPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-input)。

### 2.5 坐标应保留原始几何，裁剪只能发生在明确的截图变换中

负坐标不必然表示窗口失效，多显示器和最大化边框可能出现负坐标。应区分最小化、最大化扩展边框、屏幕外、其他显示器和 DPI 虚拟化。若为了测试将窗口放入工作区，使用目标显示器的工作区并记录变更。

不要将窗口矩形直接夹紧后继续用原坐标系点击。若截图裁剪了左侧/顶部，必须记录裁剪原点并补偿。显示器交集为空或目标点不在有效画布时拒绝真实点击；后台消息和窗口捕获应按各自可用条件判断，不能一概要求所有窗口矩形都完整位于主屏内。

现有 `stage1.txt` 记录画布 `905×514 @ (295,113)`，同批基线 PNG 为 1200×800，侧栏和图形区在画面中的布局需要逐项对齐。这提示应检查 DPI、取证前后 resize 和缓存时机；目前不足以指定一个确定缩放系数。不要直接猜测乘以 1.25。

### 2.6 导出步骤按状态识别，不能固定成唯一对话框顺序

报告不同轮次对 Export Graphics、Save As、Export image 的顺序相互修订，后续还发现格式下拉框。先记录每个对话框的标题、所属窗口、控件语义、进入条件和下一状态，采用有界状态机，而不是固定等待后寻找“任意第一个 Edit/ComboBox”。格式可在不同位置出现，最终以目标格式选中状态和真实文件解码确认。

现有 `exported.png` 文件头 `4D 4D 00 2A` 表明是 TIFF；仅 206 字节且尚未解码，不能认定是有效完整 TIFF。PNG 验收应包括文件本次创建、PNG 签名、解码成功、像素尺寸和内容正确。另存工程也需重新打开验证结构、视角和所需样式，不能只看文本包含 STRUC。

## 3. 当前增量代码的具体改进项

### P0：双击代码先恢复窗口状态再计算屏幕坐标

`realdblclickat` 目前先 `ClientToScreen`，再 `ShowWindow(..., 9)`；恢复窗口可能改变几何，之前得到的屏幕坐标会过期。建议顺序：验证窗口 → 必要时恢复 → 等待布局稳定 → 获取最新画布 → 坐标转换 → `WindowFromPoint` 并检查所属链 → 发事件。命中根窗口还不够，要确认点位属于目标画布，排除弹窗、面板和遮挡。

### P0：临时置顶必须恢复原状态

新增 `topmost` 与 `realdblclickat(topmost=true)` 会改变窗口置顶状态，但 `RestoreEnv` 只恢复光标和前台窗口，没有恢复置顶。应记录原 `WS_EX_TOPMOST`，在事务 finally 中恢复，失败也要清理；不能一律设为 NOTOPMOST，因为用户原本可能就置顶。默认不依赖置顶完成拾取，保留为明确诊断选项。

代码的 `SetWindowPos` flags 为 `0x0003`（仅不移动、不缩放），没有禁止激活的标记，且双击路径还主动 `SetForegroundWindow`；注释“不需要抢焦点”不能用于描述这段行为。置顶和键盘焦点是两回事。[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

### P0：连续动作统一事务，检查实际命中和选择

不要每次点击、双击、按键都独立恢复前台，再假定选择/焦点未变。在选择→核验→隐藏这一小段内保持统一会话和焦点；事务前后记录前台窗口、焦点子窗口和目标点命中窗口。双击时间间隔应基于系统配置并记录，不能仅依赖固定 sleep。首击是否只是激活窗口也需与原生操作对照。

### P0：结构删除绑定目标对话框并独立核验

`deleteAtomInVesta` 新增复用 Edit Data 对话框，但通过全局 `listControls('dialog')` 和标题选择，仍不能证明属于指定目标窗口。应按 PID、owner 关系、主窗口和文档核实；有歧义直接返回候选。对话框应在选择行后重新观察，使用当前行数据确认原子身份，再删除，并在返回成功前读取实际结构差异。

`pickVisibleAtomGrid` 重试固定的一组旧句柄，只适合暂时未布局；若控件已重建，重试无效。每次恢复性重试应重新枚举控件；保留最近一次错误和诊断，区分“宿主返回空”“表隐藏”“句柄失效”“不匹配”，不要统一叫竞态。报告单次 2→1 不足以称为稳定，需记录重复试验次数和失败。

### P1：将实验探针整合到正式插件入口

临时脚本里的成功不等于 DSH/MCP 已可使用。当前增量只修改 core 和宿主，未见 `index.js` 新增 Select / 双击 / 隐藏的公开语义契约。先固定可用后端，再通过注册工具的真实 execute 路径调用并验证 schema；DSH 与 MCP 都测试，不要求立即暴露所有底层原语。

### P1：模态消息规则收窄并保留完成核验

同步 SendMessage 会等待目标窗口过程返回，可能因模态处理阻塞；异步投递适用于启动此类动作，但异步返回不代表对话框已经出现。当前正式 `Cmd` 已使用 PostMessage，报告应标明阻塞发生在哪份实验脚本，避免误称生产代码仍未修复。后续应检查投递成功，再等待匹配 owner 的对话框出现；有界超时返回已知状态。[SendMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessage)。

## 4. 下一轮最小实验：先做人工与自动化对照

人工基线只用于一次性定位，不是最终要求用户手动操作。若由 DSH 自行执行，请使用其可靠的人工等效前台控制工具；若这种通道尚未可靠，请用户示范一次并留截图/步骤。

| 编号 | 只改变的因素 | 操作和记录                                                | 通过后才能做什么       |
| -- | ------ | ---------------------------------------------------- | -------------- |
| E0 | 原生交互基线 | 同一固定结构与布局，用实际键鼠选择一个清楚无遮挡的球；记录真正的 Select 入口、点击方式和反馈   | 确认本版可选取及其可观察结果 |
| E1 | 取证一致性  | 固定窗口后重新测量句柄、画布、DPI；原始截图标出画布和目标；移动光标到目标后再核对屏幕位置，不立即点击 | 校准坐标变换         |
| E2 | 输入来源   | 在 E0 的同一模式、目标与焦点下替换成自动前台点击，记录转换后坐标、命中 HWND、事件和反馈     | 自动选择单球         |
| E3 | 后端     | 在 E2 成功基线下仅替换为后台消息；失败则保留前台作为正式可用路径                   | 评估后台支持范围       |
| E4 | 后续动作   | 保持同一事务，确认只有目标被选择，再发图形区 Delete；检查局部画面与实际当前结构          | 单球隐藏通过         |
| E5 | 恢复与重复  | 在无既有隐藏对象的测试副本中恢复；重复试验并报告成功/失败次数                      | 建立小范围稳定性证据     |
| E6 | 泛化     | 再逐项改变 DPI、窗口尺寸、遮挡、多选和文件；每次重新观察                       | 逐项扩大能力矩阵       |

如果 E0 失败，先查本机操作方式与布局，不继续写自动选择代码；如果 E0 成功、E1 失败，修坐标；E1 成功、E2 失败，查事件目标/焦点/时序；E2 成功但验证读不到身份，则将“视觉选中”和“身份解析”分别实现，禁止捏造身份，也不要把后者全部堵在前者之前。

## 5. 验证结果结构与试验文件

为每次试验保存一个 JSON 清单，至少记录：runId、时间、源码版本/补丁摘要、VESTA/宿主架构、Windows、DPI、显示器工作区、主窗口/画布及 owner、窗口状态、截图路径/尺寸/裁剪变换、动作前后焦点、目标坐标和命中窗口、输入方式/事件数量、选择反馈、结构摘要、产物、结果与失败原因。

状态分开记录：`inputSent`、`selectionObserved`、`identityResolved`、`effectVerified`。用例结果为 `passed / failed / blocked / skipped / inconclusive`；整体里程碑以必要条件汇总，不将依赖阻塞算作功能失败，不将局部成功视为整个里程碑完成。

最小可复现脚本应进入仓库并由显式 GUI 开关启用，证据清单使用相对路径。当前 `D:/calcf/m-report/m1*` 目录在本次列举中没有文件；若选择试验日志另存，应给出精确路径和快照清单，不能仅写一个宽泛目录。对外分享日志前移除最近文件列表和个人路径。
