# 路线图 M0 实测记录与问题归因

> **2026-10-28 复核说明（当前阅读入口）**：本文按轮次保留 DSH 的原始实测和推断，部分早期结论已被后文修订，另有推断仍缺对照证据。请先读 [复核与下一轮建议](VESTA-INTERACTION-REVIEW.md)。Select 和单球隐藏尚未验收；工具栏哈希、黄色像素、Text Area 行数均不能单独证明模式或选择状态；版本差异尚未被证明是选取失败原因。SendInput 修复不解释 WM_SETTEXT 的失败，固定负坐标也不必然表示窗口无效。本次复核只检查文档、代码和部分已有文件，没有重跑 GUI。

> 对 `docs/VESTA-INTERACTION-ROADMAP.md` 第 2.3 / 19 / 20 节的首次真机验证
> 环境：Windows 10，屏幕 **1536×864**，VESTA 窗口（固定几何 1280×882），DPI **120（125%）**
> 证据目录：`D:/calcf/m0`、`D:/calcf/m0b`、`D:/calcf/clicktest*`
> 日期：2026-10-28

## 一、已确认的事实（有证据）

### 1. 真实鼠标输入**有效**，不是被系统拒绝

| 测试 | 结果 |
|---|---|
| `SendInput`（MOUSEEVENTF_MOVE） | 返回 **1**，光标 775,364 → **780,369** |
| `SetCursorPos` | 生效（→ 785,374） |
| `mouse_event` | 生效（→ 790,379） |
| 真实点击 **File 菜单** | 画面变化 **2.44%**（菜单弹出） |
| 随后 Esc | 画面回到基线差 **0.08%** |

**结论**：早前“`SendInput` 返回 0、注入被系统拒绝”的判断是**误判**，原因是自写 `INPUT` 结构体布局不对（少了 `dwExtraInfo` 对齐）。真实输入通道可用。

### 2. 前台锁不是问题

宿主返回的诊断：`fgBefore = fgAfter = 26479218，fgIsTarget = true`，即 **VESTA 就是前台窗口**。
所以“点不到 VESTA”不是前台归属问题。

### 3. 固定几何截图**把底部裁掉了**

- 屏幕高度 **864**，而 `captureFullWindow` 固定把窗口设为 **1280×882**；
- 结果：窗口底部（**Text Area 的低行 + 状态栏**）落在屏幕外；
- 因此“点球后状态栏的 `Atom: …` 读数”根本抓不到，`PrintWindow` 截图也只有 882 高、看不到状态栏。

**这是自设几何导致的取证盲区，不是 VESTA 不显示。**

### 4. 左栏工具条的点击**只产生高亮，不切换模式**

- 左栏是 `ToolbarWindow32`，位置 `(18,90) 31×771`，共 8 个按钮，`idCommand` 全为 0（wxToolBar 自绘，`TB_GETITEMRECT` 返回全 0）；
- 截图确认图标自上而下为：**箭头**、**箭头+虚线框**、四向移动、放大镜、成键…
- 逐点点击 y=120…325：左栏区域哈希**每次都变化**（说明点到了控件、有高亮/激活反馈）；
- 但点击候选图标后再在画布上**拖框**：视图被**旋转**（差异 16–17%），**黄色选中像素恒为 11**（基线）→ **没有进入框选模式**。

### 5. 点球 / 双击球都**没有选中反馈**

- 单击球心：画面差异 **0.09%**（仅为光标图标本身），Text Area **新增 0 行**；
- 双击球心：差异 **0.00%**，Text Area 仍 0 新增行；
- 结构表始终 2 个原子（说明既没删也没改结构）。

**结论**：本环境下“单击/双击原子即可选中”**不成立**（与路线图 19.1 对双击的描述不符，至少在该版本/该模式下）。

### 6. Text Area **不记录拾取**

- 基线 33 行；点击/双击后仍 **33 行**，无 `Atom`、无坐标输出；
- 之前看到的 `Atom: N Si …` 是**状态栏**内容，而状态栏是 wx 自绘，`SB_GETTEXT` 读回空串。

### 7. 窗口在自动化过程中**两次消失**

- 现象：`findRunningVesta()` 从有窗口变为空；
- 尚未确认是 VESTA 自身退出、还是被我们的 `Esc`/`realkey`/宿主重启间接影响；
- 需要下一步用进程退出码/事件日志定位（当前未确认，列为待查）。

## 二、与路线图的偏差

| 路线图预期 | 实测结果 | 影响 |
|---|---|---|
| 19.1 “任意模式下双击可选中单个对象” | 双击无任何反馈 | M1 的“双击兜底路径”不成立 |
| 19.1/20.7 “Select 模式单击选中，Text Area 输出信息” | 未进入 Select；Text Area 不输出 | M1 需要先解决“进入 Select” |
| 20.4 截图坐标映射 | 窗口高于屏幕，底部被裁 | 先修窗口几何（≤ 屏幕高度） |
| 20.5 双后端：后台消息 / 前台真实输入 | 前台真实输入可用（菜单可点）；后台消息对画布无效 | 与预期一致，但**画布选择仍缺** |

## 三、已确认为“下一步才能解决”的问题

1. **左栏哪个图标是 Select、点击是否真的切换模式**：需要更严格的判定——点击后把鼠标移开再截图，区分“悬停高亮”与“激活态”；并按图标真实中心（从 `palette.png` 量得约 45–50px 间距）逐个慢点击、验证。
2. **框选起点**：可能必须从原子/空白特定位置起拖；路线图未明确，需实测。
3. **状态栏读数**：窗口必须先缩到屏幕内（如 1200×800），否则永远看不到 `Atom:`。
4. **窗口消失原因**：需记录 VESTA 进程退出码与退出时机（是否被 Esc/焦点操作触发）。

## 四、结论

- 该环境**具备**真实输入能力（菜单已证明），因此路线图的“前台真实输入”后端可行；
- 当前阻塞点不是权限/前台锁，而是**工具模式切换**与**取证几何**：
  - 取证：窗口 882 > 屏幕 864，底部信息被裁；
  - 交互：左栏点击有高亮但不切换模式，点球无选中反馈；
- 路线图 19/20 节中“双击选中”“Text Area 输出选中信息”两条需按本实测**改写**为“待版本验证”，不能作为验收前提。

## 五、补充实测（同日第二轮，全部有截图/哈希证据）

### 5.1 左栏工具点击**确实切换了模式**（不是悬停）

做法：点击图标 → **把鼠标移到画布远端** → 再抓左栏区域哈希。

| 操作 | 左栏区域哈希 | 判定 |
|---|---|---|
| 基线（鼠标远离左栏） | `EEC7C832` | — |
| 点 y=126（第 1 个图标）后移开 | `30974C84` | **状态改变 → 模式已切换** |
| 点 y=186（第 2 个图标）后移开 | `E80F0C77` | 状态改变 |

结论：此前“左栏点不动”的推断错误；点击有效，且切换是**持久状态**，不是悬停高亮。

### 5.2 但“点原子 → 出现黄色选中”仍未成功

- 从**新截图**里按“蓝色球团质心”取 6 个候选点，逐个单击：黄色像素恒为 0（基线 0）；
- 对同一批候选点做**双击**：仍为 0；
- 换到 1200×800 窗口、按“高光质心”再试：黄色恒为 15（基线），无变化。

说明：在当前实测的这两种模式与这批坐标下，**点击原子没有产生选中标记**。
这不排除“某个尚未定位的图标才是 Select”，但已排除“点击完全无效”。

### 5.3 窗口几何/位置会让后续所有操作**静默失效**

- 屏幕 1536×864，窗口若设 1280×882，底部（文本区/状态栏）落在屏幕外；
- 中途一次测量得到画布坐标 `-25322,-25548`，即窗口被移到屏幕外/最小化；
  此时所有截图与点击都在“看不见的地方”执行，结果全为 0，极易误判为“VESTA 不响应”。

**规则**：每次动作前必须校验 `IsIconic == false`、`GetWindowRect` 在屏幕内、窗口尺寸 ≤ 屏幕可用区域；否则先恢复/重设几何。

### 5.4 仍未确认（下一轮要解决）

1. 左栏 8 个图标中**哪一个**是 Select（已能切换模式，需用“选中反馈”逐个验证）；
2. VESTA 该版本选中是否需要“单击 + 特定按钮态”或“先框选一次”；
3. 状态栏 `Atom:` 读数（需窗口高度 ≤ 800 才能露出）；
4. 之前窗口消失一次的具体原因（进程退出 vs 被移动/最小化）。
