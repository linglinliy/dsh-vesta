# DSH–VESTA 交互能力优化规划

> 面向实施者的规划与验收文档｜基于本地 `dsh-vesta` 0.0.2（commit `32ec9e2`）的静态检查｜2026-10-28
>
> **最新验收意见见 [验证提交第二轮复核](VESTA-VERIFICATION-REVIEW.md)**；早期实施意见见 [复核与下一轮建议](VESTA-INTERACTION-REVIEW.md)；历史实测见 [首次记录](VESTA-INTERACTION-FINDINGS.md) 和 [M0–M5 分轮报告](VESTA-M0-M5-TESTREPORT.md)。M0 部分通过，M1 选择与 M2 单球隐藏尚未验收；按能力项记录状态。
>
> 核心目标：用户用自然语言描述 VESTA 中看到的对象和想做的操作，DSH 能识别目标、选择正确的操作、执行并验证结果。先解决真实交互，再逐步扩大功能覆盖。

## 1. 目标与范围

项目已有 VASP 解析、可视化、VESTA CLI 和 Win32 控制能力。下一阶段应把重心放在 **VESTA 当前窗口的可靠交互**，而不是继续增加与交互无关的工具数量。

期望体验：

- “把画面右上角那个蓝色的球去掉。” DSH 能定位候选、理解这是显示操作还是结构编辑、执行并报告结果。
- “把这个原子删掉，做一个空位。” DSH 能识别结构位置，说明对称性和周期性影响，保存可恢复的结构副本，并验证编辑结果。
- “把这一组球隐藏，然后换一个角度、量一下这两个原子的距离。” DSH 能在同一个 VESTA 会话中连续操作。
- 用户无须知道控件句柄、菜单 ID、分数坐标或 VESTA 内部术语。只有对象含糊、操作语义不清或影响范围无法确定时才需要澄清。

本规划是实现路线，不承诺 VESTA 的所有内部功能都可通过公开接口或后台消息控制；每项能力必须先在目标 VESTA 版本上实测，再标注支持范围。

## 2. 关键案例：两个结构原子，画面中有 28 个球

### 2.1 先区分三层对象

1. **结构位点**：输入文件或 VESTA 结构表中的原子位置。
2. **对称等价位置**：根据空间群由位点生成的位置。
3. **显示对象**：根据周期平移、绘图边界、键搜索等在画面中生成并显示的球。

两原子结构显示 28 个球是可能的，但具体原因需要读取结构、空间群、边界及 VESTA 状态后判断，不能仅根据数量假设全部是周期镜像。不同球可能映射到同一位点，也可能来自不同等价位置或平移。

### 2.2 两条不同的操作路径

- **只去掉图上一个球**：选择画面对象并隐藏；结构位点不变。VESTA 手册说明，在图形区选中对象后按 Delete 是隐藏对象，并非删除结构；Esc 恢复隐藏对象。边界改变会重新生成绘图对象并重置隐藏状态。
- **真正删除结构原子、制造空位**：确定晶体位点及目标影响范围；必要时先移除对称性或构建适当超胞；编辑结构数据，检查组成并保存新文件。修改一个周期模型内的位点，仍会随该模型的周期性重复，不能宣称删除了无限晶体中的唯一原子。

参考：[VESTA 交互操作](https://jp-minerals.org/vesta/en/doc/VESTAch11.html)、[绘图边界](https://jp-minerals.org/vesta/en/doc/VESTAch10.html)、[结构与对称性](https://jp-minerals.org/vesta/en/doc/VESTAch6.html)。

### 2.3 首个验收目标

对真实 VESTA 中的两原子结构，画面显示多个球：

1. 给出一个明确的画布位置，选中指定的球，并读取或可靠确认选中对象的身份；
2. 只隐藏此显示对象；对前后截图和目标邻域进行视觉核验，确认相应球消失；
3. 独立读取结构数据，确认位点数及晶胞没有变化；
4. 执行恢复，验证该对象重新显示；
5. 与单独的真实结构删除测试互不混淆。

注意：28 个球只是用户案例中的现象，不应将“永远是 28”写死在通用代码中。固定夹具可以定义其在指定 VESTA 版本与绘图配置下的预期数量。

## 3. 当前代码现状与已知缺口

以下是基于源码的观察，非全部运行时验证：

- `index.js` 的 `vesta_input` 已有 `click`、`key`、`drag`、`wheel`，以及截图哈希形式的可选验证；这为输入注入提供了基础，但哈希变化不能证明目标对象正确或操作语义正确。
- `win/vesta-ui.ps1` 有 `viewport`、`clickat`、投递按键和真实输入等原语；它们是否在目标版本、目标控件和不同桌面状态下可靠，需要专项实测。
- `vesta_control(action="delete-atom")` 调用 `deleteAtomInVesta`，针对 Edit Data 表格的一行，不是隐藏图形区中某一个显示球。`vesta_edit` 的 remove 基于结构索引或元素，也不是画面对象操作。
- `core.js` 的 `deleteAtomInVesta` 使用固定行坐标、等待时间和当前对话框查找，源码中没有在返回成功前独立断言实际删除的是预期位点；注释对是否需要真实点击还存在历史矛盾。应先核对当前行为，修正注释与测试，再用于关键操作。
- `test/gui-delete.test.mjs` 是默认跳过的真机 GUI 用例，主要覆盖扩胞后表格删行，不覆盖显示对象隐藏。用例注释和断言也与当前步骤日志存在不一致；不应把跳过或旧记录当作已验证。
- 项目已有截图、窗口控制、文本读取及真实 VESTA 经验，应复用这些基础能力。`readVestaText` 能否读取“当前选中对象”的信息、信息刷新时机和格式，需要专项验证；不可假设已经可用。
- MCP 目前将 `result.ok === false` 映射到 `isError`，而某些科学体检中 `ok=false` 代表检查未通过而非执行失败。引入交互结果契约时应一并处理，避免把有效结果误判为工具调用错误。

## 4. 设计原则

1. **语义优先**：区分选中、隐藏显示对象、恢复、改变边界和修改结构。工具名称与描述应明确动作范围。
2. **观察 → 定位 → 操作 → 验证**：每一步有可观测状态；发出 Win32 消息不等于动作成功。
3. **身份优先于坐标**：坐标只用于初始拾取；之后尽量使用 VESTA 返回的位点、坐标、对称变换及平移信息核对。
4. **不确定就说明**：选中信息不可读、对象遮挡、窗口变化或结果无法验证时，返回 `unverified` 或 `ambiguous`，不可声称成功。
5. **保护用户数据**：默认在副本上进行结构编辑，不静默覆盖源文件；对当前实时窗口操作要指出会改变窗口状态。不要全局终止 VESTA 进程。
6. **针对具体窗口**：进程、主窗口、画布和对话框均需关联并验证；一个 PID 未必足以唯一识别一个窗口。
7. **测试证据分层**：模拟测试、真实 GUI 测试及视觉验证分别报告通过、失败、跳过和环境；禁止将跳过计入通过。
8. **先确认可行性，再抽象**：针对实际 VESTA 版本实测对象选择、文本读取、隐藏与恢复，不预设 undocumented 接口一定存在。

## 5. 建议架构

### 5.1 会话与状态层

建议新增内部 `VestaSession` 抽象，标识 `pid`、主窗口 `hwnd`、画布 `hwnd`、窗口标题、打开文件、画布矩形、DPI、截图尺寸及会话版本。每次高层操作前重新验证窗口存在、所属进程与目标一致；对话框必须按所属窗口/进程过滤。切换文件、调整视图、窗口变化或编辑结构后递增状态版本，旧的屏幕坐标或候选 ID 必须失效。

考虑 VESTA 单实例、多个窗口与同一 PID 的情况；无法唯一绑定时返回候选，不擅自选第一个。可按会话建立串行执行队列，避免两次自动化互相打断。

### 5.2 观察层

复用 `vesta_capture`、`viewport`、控件枚举与文本读取，形成一次一致的观察快照：

- 时间戳、会话标识、窗口/画布句柄与截图；
- 截图坐标、窗口客户区坐标、画布客户区坐标的显式映射；
- DPI 缩放、窗口位置与截图缩放；
- 当前模式、是否有阻塞对话框、当前文件或结构标识；
- 可获得时的选中对象信息与文本来源。

先测试截图是否包含完整画布，确定客户区偏移及 DPI 换算。针对窗口移动、缩放、不同 DPI、标题栏和多显示器编写坐标转换测试。快照只能对生成它的当前会话版本使用。

### 5.3 选中对象层

建议内部表示包含：`siteIndex`、`siteLabel`、`element`、分数坐标、平移向量、对称操作、显示坐标、屏幕位置、选中来源与置信度。字段无法读取时保持 `null` 并说明，不能由截图猜出精确晶体学身份。

**优先路径 A：VESTA 自身的选择和文本反馈。** 切入选择模式，点击指定位置，读取文本区或其他可访问的选中信息，验证位点及坐标。先确认选中是单击还是双击、模式依赖、文本区获取方法以及刷新时机。VESTA 手册提供上述选择信息，但当前插件读取链路必须实测。

**备选路径 B：辅助识别。** 若 DSH 能分析截图，可提出候选画面坐标，再用 VESTA 自身反馈验证身份；也可使用临时标注截图或交互式标记。需要验证 DSH 的截图传递、坐标返回和会话接口是否支持，不能把视觉模型的猜测当作 VESTA 原生事实。

**备选路径 C：外部结构投影。** 如需通过计算几何给所有球编号，需要可靠获取相机、投影、画布尺寸、对称操作及绘图边界，并处理遮挡与 VESTA 渲染差异。现阶段把它列为研究项，先做小型可行性验证；做不到完整状态同步时不能声称精确映射。

允许用户按画面位置、结构编号、元素和坐标指定对象。多候选或遮挡时，返回候选及标注图供用户选择，不要凭最低索引盲选。

### 5.4 动作层与结果层

在已有基础输入能力上提供语义化操作，例如：`inspect_scene`、`select_display_object`、`hide_selected`、`restore_hidden`、`set_boundary`、`edit_structure`。这些名称是建议，不是现有 API；实施时可按 DSH 框架将其合并或拆分，但不得改变其语义。保留底层点击、按键作为诊断和兜底。

所有结果统一包含：执行状态 `success | failed | unverified | ambiguous`、动作类型、会话 ID、目标身份、结构是否改变、验证证据、警告及恢复途径。科学评估的 `pass | warning | fail` 与工具执行状态分离。MCP `isError` 应表示调用执行错误，不应仅由科学检查不通过推导。

建议状态机：`观察 → 检查阻塞 → 定位候选 → 选择 → 验证选择 → 执行动作 → 验证后果 → 汇报`。任何一步失败即停止后续动作，保留诊断信息，不做无边界重试。

### 5.5 输入策略

优先使用已经证实适用于目标控件的后台消息；当 VESTA 的图形画布不响应时，使用真实前台输入作为可见的兜底，明确可能移动鼠标或改变焦点。不可把“后台投递已返回”视为成功。前台输入需验证目标窗口及前台状态，并避免在用户正在操作或窗口被替换时盲目点击。是否支持双击、Shift 多选、Delete 和 Esc 的输入方式须逐项实测。

## 6. 核心场景实现路径

### 6.1 隐藏单个画面原子球（P0）

1. 绑定窗口并观察：截图、画布区域、DPI、当前结构摘要及状态版本。
2. 识别目标：对明确坐标直接拾取；对“右上角的蓝球”给候选图，必要时让用户选择。
3. 进入合适的选择模式，点击/双击目标；从 VESTA 文本或其他可访问状态读取选择结果。失败时返回未验证，不继续执行。
4. 快照结构数据及选择信息；对目标图形区执行 Delete（不是 Edit Data 表格 Delete）。
5. 检查局部画面变化，并独立验证结构位点及晶胞未变。局部视觉验证本身可能被重绘、标签或遮挡影响，应记录证据等级；无法可靠证明就返回 `unverified`。
6. 用户要求恢复时，使用 VESTA 的恢复能力并验证。Esc 按手册是恢复所有隐藏对象，不能承诺只撤销最后一个；此限制必须告知。

对边界重建、重打开文件、视图旋转及 VESTA 重启后的隐藏状态，逐项实测并记录；禁止承诺未验证的持久性。若需要持久状态，另行验证 `.vesta` 保存和恢复行为。

### 6.2 批量选择和隐藏（P1）

支持画面框选及 Shift 追加选择，先确认选中集合再隐藏。候选可按用户指定画面区域、元素或明确列表生成；不得把“隐藏某元素的一部分”扩大成全部同元素。对重叠和多对象情况，尽可能输出实际选中数量；读取不到时说明限制。验收必须包含空选、多选、取消和恢复所有对象。

### 6.3 修改绘图边界（P1）

提供按 a/b/c 分数坐标范围的语义接口，先读旧值、设新值、检查应用后的结果；说明它会重新生成画面并重置隐藏/选择状态。不要把调整边界描述为删除结构原子。对键搜索导致边界外仍显示对象的情况单独验证。

### 6.4 真实删除结构原子（P1，依赖 P0 的对象身份）

1. 从选中对象获得结构位点和对称/平移信息，判断该操作影响的是独立位点、等价位置还是扩胞后的位点。
2. 若用户意图是周期模型中的空位，明确该空位会按最终模型周期重复；根据用户所需周期和浓度决定是否扩胞。不要自动选择超胞大小。
3. 若对称性关联使目标无法独立编辑，先说明并在副本中验证移除对称性的结果；记录变更前后位点和空间群。具体 VESTA 行为以真实验证为准。
4. 复制原始结构或另存新文件；执行精确位点删除。表格行索引必须从当前结构重新解析，不得用屏幕序号直接替代。
5. 独立检查元素计数、晶胞、目标坐标和输出文件；不覆盖原始文件。对 CIF 部分占位等格式损失发出具体提示。
6. 删除前后提供审计摘要及可恢复文件；失败时保留原副本并说明残留状态。

### 6.5 常用交互能力扩展（P2）

按用户流程优先实现：旋转/缩放/重置视角、原子和键样式、标签、距离/角度测量、保存图像及打开/保存结构。每项都需定义输入、预期状态、失败方式和独立验证。已有能力应先复测并补齐语义接口，避免新增一堆只有底层坐标的工具。

## 7. DSH 对话与工具契约

- “去掉右上角的球”：默认结合上下文判断为显示操作；如同时存在结构编辑语境，询问是隐藏还是改变结构。
- “删掉原子做空位”：走结构编辑，不使用隐藏代替；影响范围或超胞大小不明时询问。
- “把红球都隐藏”：明确是当前画面的全部红球，还是一种元素的全部显示对象；颜色可能不唯一，不能据颜色推断元素。
- “刚才那个”：只在同一会话、相同场景状态及身份仍有效时复用目标；否则重新识别。
- 明确报告“已隐藏 1 个显示对象，结构未修改”或“已生成新的结构文件，原子数由 N 变为 N−1”；如果验证不足，明确报告未验证。

建议抽象输出示例（仅为设计示例）：

```json
{
  "execution": "success",
  "action": "hide_display_object",
  "sessionId": "session-id",
  "target": { "element": "Si", "siteIndex": 1, "translation": [0, 0, 0] },
  "effects": { "displayChanged": true, "structureChanged": false },
  "verification": { "selection": "vesta_text", "structure": "before_after", "display": "visual" },
  "warnings": ["恢复隐藏对象会影响当前全部隐藏对象"]
}
```

以上字段的获取能力必须逐项证明；`null`、失败和 `unverified` 均是正常结果，绝不能填入猜测值。工具 schema 的 required 字段、DSH 与 MCP 返回格式需同步测试。

## 8. 里程碑与交付

| 阶段 | 交付物 | 完成标准 |
|---|---|---|
| M0：实测与基线 | 环境探测、两原子固定夹具、手动操作录屏/步骤、可访问性调查 | 记录 VESTA 版本、显示设置、选择文本、输入和截图行为；不影响现有窗口 |
| M1：对象拾取 | 会话绑定、截图坐标映射、选择与身份读取 | 对已知球的选择有可核验身份；错误点击与空白位置可靠失败 |
| M2：隐藏与恢复 | 单对象隐藏、全部恢复、前后结构核验 | 完成第 2.3 节真实 GUI 验收；明确隐藏状态限制 |
| M3：稳定交互 | 多选、边界、状态失效、多个窗口 | 至少覆盖同 PID 多窗口、DPI、遮挡、焦点、失败恢复 |
| M4：结构编辑 | 目标映射、对称性处理、可恢复副本、空位操作 | 对固定结构确认精确坐标、元素数和输出文件；不影响源文件 |
| M5：常用工作流 | 样式、测量、视角、导出与文档 | 以用户任务端到端验证，而非仅逐个按钮冒烟 |

每阶段合并前须写明实际运行的环境、证据、跳过项与未实现边界。阶段不是工期承诺，M0 的可行性结果可能改变后续设计。

## 9. 测试计划

### 9.1 无 GUI 自动测试

- 截图、窗口和画布坐标转换；不同缩放、偏移和非法坐标。
- 对象身份解析：不同文本格式、多段输出、缺字段、旧选择信息、非法数据。
- 状态机：空白点击、选择失败、窗口失效、模态对话框、操作超时与取消。
- 会话版本失效、多窗口绑定、结果契约与 MCP 错误语义。
- 结构编辑：对称性、周期等价、超胞、重复位置、跨边界坐标、元素计数和原文件不变。

### 9.2 真实 VESTA 集成测试

测试显式启用，使用独立的临时夹具、临时输出和专属可识别窗口；先确认 VESTA 的单实例行为是否会接管用户窗口。不能确定隔离时跳过 GUI 测试并说明，不得关闭或覆盖用户会话。只清理测试自身可证明拥有的进程与文件；使用超时和 finally。

最低覆盖：

1. 两位点、多个显示球：按已知位置选择并读取身份；空白位置和错误位置不能伪报成功。
2. 隐藏一个球：目标局部画面变化、位点与晶胞不变；恢复全部隐藏对象并检查。
3. 两个不同显示球映射至同一位点的情形（由夹具和 VESTA 信息证实），验证隐藏一个不会被误报为结构删除。
4. 调整边界：验证显示对象重新生成及隐藏状态变化。
5. 真正的结构删除：从副本执行，检查精确目标、元素计数、原始文件及新文件。
6. 两个窗口、移动/缩放窗口、DPI、遮挡、切换文件和模态弹窗；核验目标窗口不串线。
7. 前台/后台输入的成功与失败路径；测试结果记录 VESTA 版本、Windows、DPI 和输入方式。

视觉比较不能只用整图哈希：同时记录目标邻域、选择反馈和结构数据；任何单一截图差异都不是选中正确对象的充分证据。必要时保存测试失败截图，避免把用户真实数据放入仓库。

### 9.3 测试结果报告

分别汇总通过、失败、跳过；写出真实 GUI 是否执行、夹具来源、VESTA 路径和版本、Node/Windows 版本。CI 可覆盖无 GUI 测试；真实桌面 GUI 测试应明确为独立环境任务，不能由普通 CI 结果代替。移除相互矛盾的历史注释与过期文档。

## 10. 风险和决策点

- **获取选中信息**：VESTA 手册说选择后会输出信息，但本插件是否能稳定读取文本、识别更新和绑定窗口尚未验证。M0 必须优先攻克。
- **目标遮挡与重叠**：图像中看见的球可能遮住其他球，画面坐标与用户意图未必一致；不能承诺自动辨识所有复杂场景。
- **后台消息**：不同控件和版本可能不响应；提供真实输入兜底并实测，不保证无焦点操作总能成功。
- **DPI 和多窗口**：坐标换算、截图来源及句柄绑定错误会导致误操作。每步重新验证会话状态。
- **隐藏持久性**：Esc 和边界变化的影响按手册处理；保存、重启和重新加载行为需要逐版本验证。
- **数据修改**：对称性、超胞和格式转换可能影响材料模型或信息完整性；仅按用户意图执行并留存副本。
- **时间与性能**：增加观察和验证会有等待成本，先保证正确性，再基于实测优化；不使用固定等待代替状态判断。
- **范围管理**：不要在 M0–M2 尚未验收时扩展大量新工具。可先形成可复用的观察和动作层。

## 11. 交付给 DSH 的执行指令

请先阅读本文件、项目 `README.md`、`docs/VESTA.md`、`index.js` 中 `vesta_input` 和 `vesta_control`、`core.js` 中窗口/文本/删除相关实现，以及 `win/vesta-ui.ps1` 和现有 GUI 测试。

1. 先以 M0 为目标验证目标机器的 VESTA 版本、独立窗口机制、图形区选中、选中信息读取、Delete 隐藏和 Esc 恢复；记录实际证据与不可用项。
2. 根据真实结果实现 M1 和 M2：可靠绑定窗口、坐标映射、目标识别、单球隐藏与恢复、结构不变性核验；避免改动用户原始结构。
3. 为纯逻辑和真实 GUI 分别添加必要的测试，明确跳过原因；运行与变更相适应的检查。不要把历史测试结果或截图哈希变化当成新的验收证据。
4. 只在前述能力可验证后推进 M3/M4；若 VESTA 内部状态不能读取，给出实际可行的替代路径和限制，不伪造成功。
5. 交付时报告改动文件、实际通过/跳过的测试、环境、已知限制，以及完成第 2.3 节案例的证据。

这是一份规划，不要求绕过用户授权或直接修改现有真实计算数据。优先让最典型的画面交互端到端成功，再沿同一架构逐步扩展。

## 12. 最终目标：把 VESTA 当作完整工作环境来操作

前面的单球隐藏是第一个纵向验证案例，**不是本规划的终点**。最终目标是：用户用自然语言表达材料结构工作中的意图，DSH 在当前 VESTA 会话中完成观察、规划、执行、校验、修正和交付，覆盖从打开数据到制作最终图像或导出模型的完整工作流。

“完全轻松”应理解为用户无需亲自查菜单、填写大多数技术参数或反复纠错；它不是承诺所有 VESTA 版本、所有对话框以及无法公开访问的内部状态都一定可自动化。插件必须明确区分：已实现并验证、已实现但有条件、可手动兜底、尚不可达。最终体验以实际工作流成功率衡量，而不是以工具数量或菜单覆盖率代替。

### 12.1 用户应该能够怎样使用

以下是最终目标的代表性任务，方括号是期望插件处理的细节，并非要求用户必须知道的参数：

- **打开和认识结构**：“打开这个 CIF，告诉我有哪些元素和晶胞信息，把结构转到能看清层间的位置。”［识别文件、绑定窗口、读取结构、调整视角］
- **整理画面**：“把右边多出来的几个球去掉，晶胞线变细一点，背景改白色。”［识别显示对象、隐藏或调整边界、编辑样式、验证结构不变］
- **编辑结构**：“生成 3×3×1 超胞，在指定碳原子附近放一个吸附原子，保存为新的 POSCAR。”［建立模型、定位目标、坐标和单位转换、结构校验、另存］
- **测量与分析**：“量一下这个原子和周围三个原子的距离，把结果标在图上。”［目标选择、周期关系、测量、标签与单位］
- **配位与成键**：“只显示某元素周围的配位多面体，调整键长范围和颜色。”［对象范围、键规则、多面体定义和外观］
- **体积数据**：“打开这个 CHGCAR，显示正负两个等值面并调成不同颜色。”［输入种类、数据单位、正负阈值、效果确认］
- **晶面与方向**：“沿指定晶向观察，画出指定 Miller 指数的晶面并导出。”［方向与晶面语义、坐标体系、视图核验］
- **制图与交付**：“按论文插图风格排好视角，导出透明背景高清图，同时保存可继续编辑的工程文件。”［样式、分辨率、透明性、输出路径、项目状态验证］
- **连续修改**：“把刚才那张图的球缩小一点，再多显示一层原子。”［沿用同一会话与目标，状态变动后重新观察］

实现时应从用户提供的真实需求样本中补充任务，不把上述示例误认为对 VESTA 全部功能的穷举。

## 13. 能力地图与实现优先级

下表用于指导逐步覆盖。优先级按典型用户价值与依赖关系排序；状态必须依据实际版本逐项测量，下面的“路径”都是候选方案，不代表已经实现或已经验证。

| 层次 | 能力域 | 用户目标 | 可能实现路径 | 初始优先级 |
|---|---|---|---|---|
| 会话 | 安装、启动、打开、窗口绑定、当前文件 | “打开这个结构，继续刚才的工作” | 复用启动、进程与窗口枚举；绑定 PID、主窗口和文档；应对单实例复用 | P0 |
| 观察 | 截图、结构摘要、窗口/对话框、选中对象、当前设置 | “现在显示了什么” | 截图 + Win32 控件 + VESTA 文本/文件导出；不可读状态标未知 | P0 |
| 目标选择 | 点选、框选、多选、周期像、对象身份 | “选中右上角的球/这几个原子” | 图形区拾取 + 选中反馈 + 会话状态；截图辅助定位 | P0 |
| 显示 | 隐藏/恢复、边界、标签、晶胞线、背景 | “去掉多余的球，让图更清楚” | 图形区动作、边界与样式对话框；区分会重置隐藏状态的操作 | P0–P1 |
| 视图 | 旋转、缩放、平移、指定方向、适配画面 | “从侧面看、沿晶向看” | 已有输入原语；对可定量方向优先使用 VESTA 设置并核验 | P1 |
| 样式 | 球半径、元素颜色、键颜色和粗细、模型类型 | “碳用灰色、原子球小一点” | Style 对话框或经过验证的工程文件模板；读取并检查目标元素及结果 | P1 |
| 建模 | 位点编辑、替换、增删、超胞、对称性、导入导出 | “建一个含空位的超胞” | 原生 VESTA 编辑和可验证的结构文件处理；输出副本、检查模型 | P1 |
| 几何 | 距离、角度、二面角、周期邻居、标注 | “量这两点间的距离并标出” | 选择对象 + VESTA 测量；对独立计算明确周期选择并交叉核验 | P1–P2 |
| 键与配位 | 键规则、截断距离、配位多面体和显示 | “突出某原子的配位环境” | 语义化操作 Bonds / Polyhedra 等对话框；验证范围与选中对象 | P2 |
| 晶体学 | 晶向、晶面、切面、对称性及相关参数 | “沿 [001] 看并显示 (110) 面” | 原生对话框、数据读取；核对指数与坐标约定 | P2 |
| 体积数据 | 加载体积、等值面、截面、颜色与透明度 | “显示差分电荷密度的正负等值面” | VESTA 数据和对象设置；检验文件类型、阈值单位与输出 | P2 |
| 成果 | 工程保存、结构导出、图片导出、恢复会话 | “保存工程和高清图” | VESTA CLI / GUI 或已验证的文件格式路径；核验路径、格式、尺寸及可重新打开 | P1–P2 |
| 高级 | 更复杂的多相、结构因子、衍射及其他 VESTA 功能 | “完成一项具体高级计算或可视化” | 按官方功能逐一调研、建立验证夹具和原生操作流程 | P3 |

每个能力域必须建立逐项能力卡：**用户任务、输入、前提、步骤、结果、可观测证据、回退方法、版本/平台、限制、测试和当前状态**。同一类功能可以有多个能力卡；不因为菜单能打开就将整类标记为已支持。

## 14. 以工作流为单位的完整路线

### 阶段 A：可靠的 VESTA 控制基础

完成 M0–M2，以及会话识别、场景观察、坐标映射、目标选择和核验。交付一个能在当前窗口持续工作的交互闭环。目标样例：打开结构 → 识别一个显示球 → 隐藏 → 恢复 → 保存截图。所有操作要能说明作用窗口与结果。

### 阶段 B：日常看结构和做图

补充视角、显示边界、原子/键样式、背景、标签、晶胞线与图片导出。先支持确定性高的指定参数，再支持“清晰一些”“适合论文”等意图：由插件提出具体参数或展示预览，并根据用户反馈迭代。不能把某种审美预设声称为普适标准。验收包含一条完整任务：打开 → 调整 → 预览 → 修改 → 输出图片和工程文件。

### 阶段 C：结构建模与几何

实现明确作用范围的超胞、位点编辑、替换/添加/删除、对称性处理、测距和标注。涉及结构改变时保留输入副本、记录变更与单位，并验证导出文件。验收以真实材料建模流程为单位，包括模型创建、目标位点核对、测量及重新打开导出的结构。

### 阶段 D：配位、晶面与体积数据

补充键与配位规则、多面体、晶向和晶面、体积文件加载、等值面及截面。每种数据类型单独标注单位、输入要求和 VESTA 版本差异；按真实文件验证截图、参数和保存结果。不要将独立后处理输出自动描述成 VESTA 原生计算。

### 阶段 E：覆盖更多高级工作与适配

依据用户实际使用频率和 VESTA 官方功能清单，补齐多相、衍射、结构因子等高级功能。建立版本兼容矩阵、可访问性研究、自动恢复能力和替代路线。每项先做可行性实验与独立交叉核对；不可达项目保留手动步骤与明确状态，而不是无限重试或虚报已支持。

## 15. 实现路径选择与兜底规则

应按操作选择最可靠的通道，统一由语义层向 DSH 暴露；不要求所有操作都靠模拟鼠标。

1. **VESTA 官方 CLI 或可验证的文件导入导出**：适合已有官方命令、可重复的转换和图像导出。校验输入、退出状态和产物，不假定 CLI 覆盖 GUI 当前未保存状态。
2. **可验证的工程文件或结构文件操作**：适合结构和样式中有稳定、已理解表示的部分。先确认格式、版本、数据损失与重新打开效果；直接改文件不能冒充当前窗口已更新。
3. **原生菜单与对话框控件**：适合可访问的语义控件，依据窗口所属关系、控件状态和操作后值确认。不要仅依赖固定坐标、控件 ID 或固定等待时间。
4. **图形区选择与输入**：适合选择画面对象、调整视角等 GUI 原生交互。提供准确的坐标换算和选中反馈，优先使用经过验证的输入方式，必要时明确采用前台输入。
5. **辅助视觉识别与人工指认**：用于目标定位和复杂状态确认；视觉坐标是候选，尽量由 VESTA 自身反馈核实。当自动识别不可靠时，让用户指认或给出下一步手动操作。

每条路径都需要原型验证、能力边界和回退。切换通道前后必须保证针对同一文件与会话；用户更改、外部弹窗或窗口关闭时先重新观察。以“发出了操作”作为成功条件的实现不得进入稳定能力清单。

## 16. 通用交互闭环与恢复

对每一个高层任务，DSH 应遵循：

1. **理解意图**：判断目标、作用范围、需要改变的状态、期望产物；对“漂亮一点”等开放要求提出可操作方案。
2. **检查上下文**：确定当前窗口、打开文件、可用功能、数据类型、未保存修改和阻塞对话框；用户上下文变化时重新读取。
3. **制定小步计划**：将任务拆成可观察的操作与验证点；对结构编辑、导出或可能影响既有内容的操作提前准备可恢复方案。
4. **执行和核验**：逐步动作，读取实际状态或产物；必要时显示截图预览；失败立即停在已知状态，不通过盲目重复扩大影响。
5. **修正与交付**：允许用户针对画面继续调整，最终报告已做的操作、文件路径、关键参数及仍不能确认的事项。

恢复能力应按类型分别定义：视角输入的反向操作、VESTA 本身的撤销能力、隐藏对象的全部恢复、工程另存副本和结构文件回滚不能混为同一套“万能撤销”。若某操作不能可靠撤销，执行前保留副本并说明。日志记录操作、目标、条件、证据和结果，避免记录不必要的本机敏感数据。

## 17. 完整目标的验收与项目治理

建立一个来自真实用户的任务集，覆盖第 13 节每个能力域，并包含简单任务、连续修改、错误输入、多窗口和可恢复性。每项至少记录：起始文件与环境、用户指令、预期结果、实际结果、验证方式、用户是否必须介入、耗时及失败原因。对科学结果额外记录单位、参考结果和允许误差。

建议发布时报告以下指标，目标值根据基线和真实用户协商后设定，不预先捏造：

- 端到端任务成功率，以及自动完成与需要用户介入的比例；
- 目标识别正确率、误操作次数和无法判定次数；
- 已支持功能中有真实 VESTA 验证的比例，以及失败、跳过、版本覆盖情况；
- 对结构或工程文件的非预期改动数、成功恢复率；
- 主要工作流的完成时间、用户步骤数，以及不同 VESTA/Windows/DPI 条件下的稳定性。

每次版本更新维护一张能力矩阵和已知限制清单；新能力必须有对应用户任务及验收证据。先为核心工作流设定版本里程碑，再根据实际反馈调整优先级。凡是“所有功能”“完全自动”之类的宣传，必须受矩阵和测试证据约束。

## 18. 给实施者的最终目标补充指令

请将本文件视为**覆盖整个 VESTA 用户工作流的长期规划**。单球隐藏只是 M0–M2 的首个落地目标；不要完成它后即宣布终极目标实现。先建立统一会话、观察、目标识别、语义动作、验证与恢复的基础，再按第 13–14 节逐项交付常用绘图、结构建模、测量、配位、晶体学、体积数据和成果导出。每轮选择真实用户工作流，建立可复现验收；对于 VESTA 版本、私有控件或无法可靠读取的状态，明确记录实际能力与替代路径。

## 19. Select 模式与对象选取的专项实现

Select 是画面交互的基础能力，必须作为独立里程碑实现；隐藏、测距、配位和结构编辑均可复用选取结果。这里的“选中”指 VESTA 图形区的对象选择，不等于 Edit Data 表格中选中一行。

### 19.1 用户能力与 VESTA 语义

至少支持以下用户任务：

- 选中画面中某一个球，报告实际选中对象。
- 在已有选择基础上追加或移除目标；区分替换选择和追加选择。
- 框选画面中的一组对象，并在后续隐藏或测量前确认目标集合。
- 清除当前选择、读取选中状态；在可观测条件不足时明确返回无法确认。
- 依据截图选择目标，并在视角、窗口尺寸、结构、绘图边界或选择模式变化后，拒绝复用过期画面坐标。

VESTA 手册说明，使用竖直工具栏的 Select 模式可左键单击对象、拖拽框选，按住 Shift 可以追加选择；不论当前操作模式，单个对象也可用双击选择。单个对象被选中后，Text Area 可输出对应信息。以目标版本的真实测试为准，尤其要核对选中反馈、双击和修饰键的实际行为。[官方手册：Select](https://jp-minerals.org/vesta/en/doc/VESTAch11.html)。不要假设 Delete 是清除选择：它在图形区用于隐藏已选对象；Esc 恢复隐藏对象的影响也不可称为仅清除选择。

### 19.2 操作流程和接口建议

内部实现建议拆分为：`get_selection_mode`、`set_selection_mode`、`select_at`、`select_rectangle`、`get_selection`、`clear_selection`。这些是规划中的语义动作，不代表已有接口；公开 API 可按宿主工具数量约束合并，但必须保留明确的模式、选择方式与结果。

1. **观察与绑定**：识别 VESTA 目标主窗口及图形画布，获取截图、画布区域、DPI 和场景版本。若多窗口或模态弹窗无法消歧，返回候选或错误。
2. **进入 Select 模式**：优先从工具栏读取当前模式及 Select 控件状态，通过可访问控件或已验证的按钮点击切换；每次操作后观察是否真的进入该模式。若模式无法读取，标记为待验证；双击选取可作为经过实测的替代路径。不要假设某个按钮坐标或快捷键跨版本固定。
3. **目标与坐标**：明确截图坐标、窗口客户区和画布客户区之间的映射，并携带截图 ID/场景版本。画面已改变时重新截图。目标被遮挡、描述含糊或有多个候选时，返回候选或请用户指认。
4. **执行**：单选使用已验证的单击/双击；追加选择使用 Shift + 点击；框选使用鼠标按下、拖拽、抬起，并按是否追加正确处理 Shift。修饰键必须在异常时释放。先试后台消息，再视实际效果选择前台真实输入；检查窗口焦点并避免操作误入其他窗口。
5. **核验**：截图检查高亮及对象变化；对单对象读取 VESTA Text Area 中的位点、元素、分数坐标、平移向量和对称信息（如果该版本可访问）。必须识别新旧选择文本，不能把上次结果当本次结果。对多选，只有在能可靠读取选择集合或得到可靠视觉证据时才返回确认数量；否则返回 `unverified`，禁止猜测。
6. **状态与回报**：返回 `selected`、`ambiguous`、`unverified` 或 `failed`，附会话、场景版本、目标、输入方式与证据。点击投递成功或截图变化不等同选取成功。后续隐藏/测量/编辑必须重新核验目标仍被选中。
7. **清除与恢复**：优先使用目标版本中经过验证的“清除选择”操作；它与恢复已隐藏对象属于不同动作。不要未经证实把 Esc 绑定为只清除选择，也不要影响用户先前隐藏的对象。

### 19.3 建议的数据契约

```json
{
  "action": "select_at",
  "execution": "success",
  "sessionId": "session-id",
  "sceneVersion": 4,
  "selectionMode": "replace",
  "target": {
    "kind": "atom",
    "element": "Si",
    "siteLabel": "Si1",
    "fractionalCoordinates": [0, 0, 0],
    "translation": [0, 0, 0],
    "symmetryOperation": null
  },
  "verification": { "source": "vesta_text", "status": "verified" }
}
```

仅当实际获取和解析到相关信息时才返回相应字段；这只是接口草案，不保证现有 VESTA 会话可以提供全部字段。对于多选状态不可读取、重叠球或仅视觉估计的情况，应使用 `null` 和 `unverified`，并将选择范围交给用户确认。

### 19.4 优先试验和验收

在独立可恢复的测试窗口完成下列试验，并记录 VESTA 版本、窗口模式、DPI、输入方式和证据：

1. 在 Select 模式单击固定夹具中的球，观察高亮并读取新的选中信息；空白处点击不得误报成功。
2. 在其他模式双击对象，核实是否可选中并读取身份；测试同一对象的周期显示像与位点映射。
3. 按住 Shift 逐个追加选择，核对是否保留先前选择；故意触发中途失败，确认 Shift 已释放。
4. 框选一组对象，验证框选区域及实际选中情况；测试窗口移动、DPI 变化、重叠对象和视角变化后的坐标失效。
5. 单选一个球后执行图形区 Delete，核对该球隐藏而结构位点不变；恢复操作及其影响单独核实。
6. 对比 PostMessage 和前台真实输入的行为，分别记录成功、失败、未验证；禁止仅用返回 `ok` 或整图哈希作验收。
7. 在同一 PID 的多个窗口、模态对话框和失焦场景下验证绑定，不把输入送到用户另一个窗口。

完成标准：用户能通过截图指认一个球，DSH 能可靠地选中并说明对象；对于无法确认的目标会停下并解释。多选和框选必须另有实测证据，不能因为单选通过而被标记为已完成。

## 20. VESTA 独立键鼠操作：完整实施与验证方案

本节是可单独执行的技术方案，目标是让 DSH 在用户给出任务后，自主观察并操作已经打开的 VESTA 窗口。第一验收案例为“选中并隐藏指定显示球”；后续同一输入基础可用于旋转、框选、菜单、对话框及复杂工作流。这里的“独立”指不需要用户亲手完成每一步；它不保证始终不抢焦点、不移动鼠标，必须区分后台消息和前台真实输入。

### 20.1 目标、边界与现状

- 输入：明确的 VESTA 窗口/会话、用户意图、目标对象或画面坐标。
- 输出：执行状态、输入方式、目标身份、前后证据、是否改动结构和可恢复方式。
- 前提：可交互的 Windows 桌面会话、VESTA 正在运行、目标窗口不被无法处理的模态框阻塞；具体版本/DPI/桌面条件必须记录。
- 安全边界：先在独立测试结构、可恢复窗口中验证；不可把已有用户窗口当临时夹具，更不可全局关闭 VESTA 或覆盖结构。图形区 Delete 是隐藏选中对象，Edit Data 的 Delete 是结构编辑，必须严格区分。
- 现有代码：`vesta_input` / `injectInput` 有点击、键、拖拽、滚轮；宿主脚本有 `clickat`、`keypost`、`realclickat`、`realdrag`、`realkey`。这些原语的存在不代表当前端到端链路已经通过，也不保证某个动作在后台生效。
- 现有 `realClickControlAt` 和 `realKeyPress` 分别保存/恢复前台环境；如果连续操作之间焦点被恢复，可能破坏选中→Delete 的链路，必须实测。`viewport` 按 PID 选主窗口的策略也不足以保证同 PID 多窗口唯一。

### 20.2 四层实现与责任

1. **窗口层**：枚举并绑定 VESTA 主窗口、图形画布和对话框，管理进程 ID、主窗口句柄、画布句柄、标题、文件和窗口状态。句柄必须来自实际枚举并验证归属；不凭标题或 PID 的第一个结果盲选。
2. **观察层**：获取当前截图、画布屏幕矩形、DPI、焦点、当前模式、阻塞对话框与可读的选中信息；给每次观察生成快照 ID 和场景版本。
3. **输入层**：提供明确的鼠标移动/单击/双击/拖拽/滚轮与键盘按下/抬起/组合键，支持后台消息和前台系统输入两种后端；明确修饰键和事件顺序。
4. **语义层**：实现“进入 Select → 选择目标 → 核验 → 隐藏”等工作流。只有验证通过才能报告动作完成；输入发送成功只代表输入已尝试。

### 20.3 窗口与会话绑定

- 从实际窗口枚举结果选择 VESTA 顶层窗口，再枚举其子窗口定位 `wxGLCanvas`；记录二者句柄、所属进程、标题、可见性、客户区、画布位置、DPI、当前文档标识。
- 针对 VESTA 单实例和一个进程多个主窗口：允许以主窗口句柄/文档身份选目标；仅提供 PID 且存在多个候选时返回 `ambiguous_window`，不默认选择第一个。
- 每次动作前验证主窗口和画布仍存在、归属关系未变，检查目标窗口是否被模态对话框阻塞。窗口关闭、文件切换、画布重建、DPI/尺寸变化或视角/边界变更使旧快照失效。
- 单会话操作串行，避免两次请求竞争焦点、改变视角或互相释放修饰键。窗口失效时停止当前事务，不沿用缓存句柄重试。
- 测试时先确认 VESTA 的单实例行为能否隔离；如果打开夹具会替换用户现有文档，就不要自动启动真实测试，改用专门桌面会话或用户提供的测试窗口。

### 20.4 截图与坐标映射

定义三个坐标空间并在结果中标明：截图像素 `S(x,y)`、画布客户区 `C(x,y)`、屏幕物理/逻辑坐标 `P(x,y)`。必须明确截图的缩放、裁剪、DPI 感知方式和 API 坐标单位，不能把截图上的坐标直接当作画布坐标。

对于轴对齐、截图与画布位于同一已知坐标体系的情况：若画布在截图中的左上角为 `(sx0, sy0)`、显示宽高为 `(sw, sh)`，画布客户区宽高为 `(cw, ch)`，则候选映射为：

```text
cx = (sx - sx0) * cw / sw
cy = (sy - sy0) * ch / sh
```

此公式只是候选：系统 DPI 虚拟化、截图缩放、非客户区和多显示器可能使单位不同。必须用实测画布边界、`ClientToScreen` / `ScreenToClient` 与截图元数据建立一致映射，先验证再使用。映射后拒绝越界坐标，不静默裁剪成另一个球。

建议先使用仅含画布的截图简化转换；如果依赖完整窗口截图，则同时获取画布相对于截图的精确矩形。提供调试模式，在截图上叠加画布边框、候选点和坐标；覆盖左上/右下、画布中心、窗口移动与缩放、100%/125%/150% DPI、多显示器以及窗口被遮挡/最小化。截图是否能可靠包含 OpenGL 画布必须实测；黑图、旧帧或只抓到遮挡物都应返回不可用，不能盲点。

任何截图必须与窗口、尺寸、DPI、视角和场景版本绑定；旋转、缩放、框选、改变边界、切换文件或窗口几何改变后，旧坐标作废。视觉上目标球重叠或被遮挡时先调整视角或让用户指认，不把最近的球当成确定目标。

### 20.5 双后端策略

**后端 A：向目标窗口投递消息。** 对已知句柄投递鼠标和键盘事件，不移动真实鼠标；优点是干扰小，限制是部分 VESTA/wx/OpenGL 操作可能依赖真实焦点、按键状态或完整事件序列。逐动作实测，不能以 `PostMessage` 返回值证明 VESTA 完成操作。鼠标按下/移动/抬起、双击消息、修饰键状态和坐标语义应符合 Windows 与目标控件要求；不同输入消息对坐标空间的要求也需分别核对。

**后端 B：前台系统输入。** 验证目标顶层窗口后置前、确认实际前台窗口与目标一致，必要时点击画布建立焦点，再通过系统输入模拟键鼠；优点是更接近手动操作，但会占用焦点和鼠标，且前台切换可能被 Windows 拒绝。检查真实焦点/目标，失败即停止，不可继续把键发到其他应用。建议以当前支持的 Windows 标准输入接口实现，并逐项测试；已有代码使用 `mouse_event` / `keybd_event`，不要因注释写“SendInput”就假定它实际调用了 SendInput。

**选择原则**：按“动作类型 × VESTA 版本 × 环境”维护经过验证的能力矩阵。可先尝试已证明有效的后台方式；失败时只有在确认未发生副作用后才进行前台回退。对非幂等操作不可盲目重试。失败后重新截图、读取选择/窗口状态，再决定是否继续。

### 20.6 输入事务与焦点管理

不要让“选择球”和“按 Delete”成为互不关联且各自恢复前台的两个动作。实现可控的**前台输入事务**：

1. 获取会话锁，重新观察并确认窗口、画布、目标和截图版本；记录当前前台窗口与鼠标位置。
2. 置前 VESTA，核实前台归属；若失败或有未知模态框，停止并返回 `focus_failed` / `blocked`。
3. 进入 Select 模式并确认；焦点不明确时在画布安全位置或已知目标上建立焦点，但不可用无关点击悄悄改变选择。
4. 执行目标选择，等待实际状态变化（有界轮询或条件判断），读取选中证据。失败即停止，不按 Delete。
5. 若用户意图为隐藏，确认选择仍有效，在同一焦点上下文中发送 Delete；观察并验证结果。
6. `finally` 释放所有按住的鼠标键和修饰键，按实际情况恢复鼠标/原前台窗口；恢复前也要确认用户没有在此期间主动切换工作，避免抢回焦点。释放动作与恢复结果写入日志。

任务成功、失败、取消和超时都需要清理；使用有界超时和明确错误，避免长时间阻塞。前台输入阶段对用户桌面有可见影响，不能描述为无干扰后台操作。执行期间如果检测到用户操作、窗口移动、焦点变化或弹出未知对话框，应暂停并重新观察。

### 20.7 Select、单选、追加与框选

- 先通过工具栏实际状态识别 Select；若无法读取，使用目标版本实测可行的选择方式，并在结果标明不能验证模式。不要硬编码未经实测的快捷键。
- 单选：根据目标版本实测，在 Select 模式单击目标；双击可作为经验证的替代。选择完成后确认高亮和/或 VESTA Text Area 的新内容；清除旧文本或记录其版本以防把历史结果当作本次结果。
- 多选：明确 `replace` 与 `add`；追加需确保 Shift 的按下和抬起与鼠标事件在同一有效输入上下文中。后台消息对修饰键是否有效必须实测；前台输入异常时必须释放 Shift。
- 框选：起点与终点均在当前画布坐标内，发送按下→移动→抬起。拖拽路径及所用模式需与旋转模式区分，避免本想框选却旋转视图；如果模式不确定，不执行框选。追加框选的 Shift 必须保持到鼠标抬起。
- 读取选择：VESTA 手册对单对象选择的 Text Area 输出有说明；本机插件是否能稳定读取、去重并区分刷新待实测。多选集合不可读时，最多报告视觉候选或 `unverified`，不要猜测数量或身份。
- 取消选择：找出目标版本中真正能清除选择的方法并验证。不要将 Esc 直接定义为只清除选择，因为手册记载它会恢复隐藏对象；不要借助 Delete 清除选择。

### 20.8 首个端到端验证脚本（实现步骤，不是假定可运行命令）

在隔离测试窗口执行，并保存阶段截图与结构摘要：

1. 打开已授权的测试结构；记录窗口 ID、画布 ID、结构位点数和晶胞。手动确定至少一个无遮挡目标球，截图标注其位置。
2. 对画布截图进行坐标映射自检。进入 Select 模式；后台单击目标，观察高亮和文本；若失败，记录证据并重新观察。
3. 在确认上一步没有意外选中后，使用前台真实单击/双击进行对照；逐项确认焦点、点击点和选中反馈。记录哪一种方式有效。
4. 选中后，在同一输入事务内发送 Delete；截图确认目标处变化，读取结构摘要确认位点数和晶胞不变。若视觉或结构检查无法确定，标记 `unverified`。
5. 使用经过验证的恢复操作；记录其影响范围。再复测目标恢复及结构保持不变。
6. 单独在副本上测试 Edit Data 结构删行，确认与第 4 步的隐藏行为不同；禁止把其结果用作单球隐藏的证明。

不要对生产窗口运行可能重置用户既有隐藏对象的 Esc；不要在未确认当前选择身份时发送 Delete。对用户现有窗口的实操应让其目标和影响明确，测试不应改变用户的数据。

### 20.9 验证矩阵与故障诊断

| 症状 | 先采集什么 | 优先排查 | 停止条件 |
|---|---|---|---|
| 截图黑屏、超时或画面不是 VESTA | 捕获方法、窗口状态、画布大小、时间戳 | OpenGL 捕获路径、最小化/遮挡、旧帧 | 无可靠截图时不进行坐标点击 |
| 点击无反应 | 实际主窗口/画布句柄、坐标叠加图、模式、后台/前台 | 坐标换算、Select 模式、目标控件、输入顺序 | 两种方式均无可核验选择时停下 |
| 点到了错误球 | 截图、变换、选中对象文本及视角版本 | DPI/截图偏移、遮挡、窗口变动 | 不能确认目标时不继续隐藏 |
| 选中了但 Delete 无效 | 前台窗口、画布焦点、选中前后截图、按键方式 | 操作间焦点恢复、按键投递目标、选择失效 | 焦点或目标不明时不重复按键 |
| 框选变成旋转 | 当前模式、拖拽坐标和事件顺序 | 未进入 Select、模式识别失效 | 停止并重新观察，避免继续拖拽 |
| 操作了错误窗口 | 枚举出的所有窗口、PID/HWND、文件标题 | 单 PID 多窗口、模态框、缓存失效 | 停止并要求消歧；不自动重试 |
| 画面变了但结构也变了 | 前后结构摘要、动作路径 | 误进 Edit Data、调用结构删除 | 停止，保留证据并从副本恢复 |
| 多选数量无法确认 | 高亮截图、Text Area 和可访问状态 | VESTA 是否暴露集合、对象重叠 | 标记未验证，不声称成功 |

日志记录阶段、目标标识、截图/画布尺寸、坐标映射、焦点、后端、事件、验证和耗时；避免默认保存用户敏感文件内容。截图和详细日志可放临时目录并提供清理方式。

### 20.10 验收交付与能力矩阵
